What does application code look like?

The spike already has one-call drivers. Its missing application layer includes familiar codec methods, a registry with detection, header-only helpers and convenient still-image results. A smaller implementation protocol has not yet delivered an equally simple caller interface.

What about simpler codec authors?

WholeImageDecode requires name, formats, probe and decode; WholeImageEncode requires name, format, accepted layouts and encode. The adapter supplies the state machine. This is useful authoring support, but decode currently receives no Pulse, every operation constructs a boxed state, and the helper has no matching check for required metadata settlement. Those limitations remain visible below. WholeImage source

Default methods can preserve the short path

Proposed Provide ordinary decode/probe/encode conveniences as defaults or extension methods that delegate to the shared checked implementation. Keep required implementation hooks small. Driver-dependent helpers belong in the caller layer so the core does not acquire a dependency back on its I/O crate.

Preserve behavior, evolve execution

A default can drive the step protocol. A native optimization can avoid a box or repeated parsing while preserving pixels, metadata, refusal behavior and cancellation. The convenience signature should not promise a particular allocation or scheduling strategy.

Keep required guarantees central

Unsupported optional operations should refuse explicitly. A required limit or retention policy must not inherit a successful no-op default. Shared admission should run before effects on both default and optimized paths.

Defaults still commit to names, signatures and behavior. Adding a defaulted trait method can introduce name ambiguity, and a new method must preserve dynamic dispatch compatibility. Generic convenience methods can live separately where necessary. Cargo compatibility guidance · Rust trait rules

Discover support; verify the actual request

Proposed Keep capability discovery for UI controls and route selection. Ordinary callers can submit a request directly and receive a named refusal. A positive general capability is not admission for every input.

Each step borrows its input. The decoder itself is Send + 'static; it cannot retain a parser borrowing the caller’s file between steps. The current spec stores SharedPulse.

What this means for a gigapixel browser

Preserve native indexes/readers, range batching, source-version checks and persistent compressed/decoded caches. Borrow the fetched tile or range where the execution boundary permits it; do not require materializing the entire large source. Keep jobs coarse enough to avoid a worker hop per row. The native Tokio timings below are not browser-worker timings. This fork has no browser integration or browser performance-parity measurement.

&dyn Pulse belongs on the local path

Caller’s slice + borrowed Pulse→Native decode→Move owned pixels

The control Pulse borrows stack counters and refuses share(). Native cancellation still reports the original timeout cause. JPEG sends progress through that borrowed Pulse; the bitmap raw APIs qualify cancellation only because they currently accept Stop.

The current WholeImageDecode::decode hook receives no Pulse. Its outer checks cannot provide native in-flight progress or cancellation on their own. The current spec’s owned SharedPulse also excludes a non-shareable borrowed observer. Both are open API work, exposed by this experiment.

Use owned bytes/control when work must escape the caller’s lifetime. A worker hop should move existing ownership or clone an existing shared handle once. Failure to share a Pulse must remain explicit; replacing it with cancellation alone would lose progress.

Keep the guarantees. Remove required machinery.

  • Restore the direct caller path: known-codec one-shots, registry detection, header inspection, convenient image results and named collection browsing.
  • Keep a local borrowed entry point: whole-file &[u8] and &dyn Pulse, with no mandatory box, runtime or shared ownership.
  • Keep the incremental/range protocol: source-owned windows, exact requests, batched rows, output ownership transfer and retained documents are useful mechanisms.
  • Qualify capabilities and I/O: actual request admission, honest support/refusal, retained cache behavior and a borrowed resident document path.
  • Restore color and metadata management: retention, authority, carrier selection, orientation and readiness need the same guarantees on every execution route.
  • Keep admission and correctness: output interpretation, source identity, exact ROI, error causes, cancellation and pre-output policy remain requirements.
  • Make authoring and scheduling optional: coroutine state, per-batch worker hops and duplicate typed/dyn hierarchies need not be mandatory costs.
  • Do not retire the fast path yet: allocation parity is demonstrated by the cost control; latency parity and the complete replacement contract remain unqualified.
